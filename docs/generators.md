# Generators

All generators live in
[packages/core/src/generators](../packages/core/src/generators). Each
exports two things:

1. A **string emitter** `generateXxx(resolved): string` — used by the CLI
   to write a `.ts` file.
2. (Optional) A **runtime builder** `buildXxxObject(resolved): object` —
   used by callers that want the raw object without disk IO.

Shared helpers — `fileHeader()`, `serializeValue()`, `serializeObject()` —
live in [utils.ts](../packages/core/src/generators/utils.ts).

## Architecture in one paragraph

PrimeVue is the **runtime source of truth**. Its `definePreset(Aura, ...)`
emits CSS custom properties (`--p-primary-500`, `--p-spacing-md`,
`--p-border-radius-sm`, …) on the document. theme-unify generates two
artifacts that both reference those variables: a PrimeVue preset that
produces them, and an UnoCSS theme whose values are the matching
`var(--p-*)` strings. Update the preset at runtime → utility classes
follow automatically. No raw hex codes leak into the UnoCSS output.

## Emit conventions

- Every file starts with `fileHeader({ meta: resolved.meta })`:
  ```
  // Auto-generated by theme-unify@0.2.0 — do not edit
  // theme: "My Theme"
  ```
  The version is read from `theme-unify`'s `package.json`. The
  `theme:` line is omitted when `meta.name` is empty.
- Exports use `as const` where it sharpens consumer types.
- Object keys that aren't valid JS identifiers are quoted by
  `serializeObject`.
- Strings use single quotes; backslashes and quotes are escaped.
- Indentation is 2 spaces.

## `preset.ts` — PrimeVue preset

Source: [generators/preset.ts](../packages/core/src/generators/preset.ts).
Exports: `generatePreset`, `buildPresetObject`, `resolveSemanticScale`.

Output (default `preset.ts`) exports a `GeneratedPreset` produced by
`definePreset(BaseTheme, { primitive, semantic, components })`, and a
`themeOptions` object suitable for PrimeVue's `app.use(PrimeVue, { theme: { options } })`.

`themeOptions` wires `darkModeSelector` based on `meta.darkModeStrategy`:
- `"class"` → `{ darkModeSelector: meta.darkModeSelector }` (default `".dark"`)
- `"media"` → `{ darkModeSelector: ".system" }` (PrimeVue's sentinel for
  `prefers-color-scheme`)

What it does:

- Emits every user-defined color scale under `primitive.<name>` (matches
  Aura's structure).
- Maps `primitive.spacing` → `primitive.spacing` (PrimeVue then exposes
  `--p-spacing-*`).
- Merges `primitive.radii` into PrimeVue's `primitive.borderRadius`.
- Emits `primitive.shadow`, `primitive.fontWeight`, and
  `primitive.font.{family,size,lineHeight}` from `primitive.typography`.
- Resolves `semantic.primary` → an object of step refs:
  `{ 50: "{blueberry.50}", …, 950: "{blueberry.950}" }`. PrimeVue
  resolves these references to the matching `--p-*` variables.
- Resolves each `semantic.extra.<name>` the same way, producing
  `--p-{name}-*` variables. Role keys are **canonicalized** before they
  are written into the preset's `semantic` block: legacy names
  `warning` and `error` become `warn` and `danger` so the generated
  preset always uses PrimeVue's official severity vocabulary
  (`primary`, `secondary`, `success`, `info`, `warn`, `danger`,
  `help`, `contrast`). Non-canonical role names (e.g. `accent`) pass
  through unchanged. See [token-schema.md → Canonical semantic roles](./token-schema.md#canonical-semantic-roles).
- Builds `semantic.colorScheme.{light,dark}.surface` from
  `semantic.surface.{light,dark}`. Step `0` is added automatically:
  `#ffffff` for light, `#0a0a0a` for dark.
- Mirrors `primitive.zIndex` onto `semantic.zIndex` so PrimeVue overlay
  components share the same stacking values as UnoCSS `z-*` utilities.
  PrimeVue's runtime overlay options
  (`app.use(PrimeVue, { zIndex: { ... } })`) can be derived from the
  same primitive block.
- Deep-merges `preset.overrides` last; refs inside overrides are resolved
  before merge.

Consumed by the playground's
[main.ts](../packages/playground/src/main.ts) as `theme.preset`.

## `uno-theme.ts` — UnoCSS theme

Source: [generators/uno-theme.ts](../packages/core/src/generators/uno-theme.ts).
Exports: `generateUnoTheme`.

Output (default `uno-theme.ts`) exports named consts:

- `darkMode` — `"class"` or `"media"`, reflecting `meta.darkModeStrategy`.
  Pass this into `presetUno({ dark: darkMode })` (or equivalent) so the
  `dark:` variant activates via the matching mechanism.
- `colors` — every palette PrimeVue exposes, mapped to
  `var(--p-{name}-{step})`. Includes user palettes referenced by
  `semantic`, every builtin actually referenced, the `surface` palette
  (with step `0`), and one entry per `semantic.extra.*` role plus
  `primary`.
- `spacing` — `Record<key, var(--p-spacing-{key}))`.
- `borderRadius` — combined `primitive.radii` and Aura's default radii
  keys, all as `var(--p-border-radius-{key})`.
- `boxShadow` — `var(--p-shadow-{key})`.
- `fontFamily`, `fontSize`, `lineHeight`, `fontWeight` — emitted only
  when the corresponding `primitive` field is set, all as `var(--p-*)`.
- `breakpoints` — literal `Record<string, string>` from
  `primitive.breakpoints`. Plugs into UnoCSS `theme.breakpoints`.
- `zIndex` — literal `Record<string, string>` from `primitive.zIndex`.
  Plugs into UnoCSS `theme.zIndex`; the same values are mirrored into
  the PrimeVue preset's `semantic.zIndex` block.
- `transitionProperty` / `transitionDuration` /
  `transitionTimingFunction` — literal records emitted independently
  per sub-bag of `primitive.transitions`. Map onto UnoCSS
  `theme.transitionProperty` / `theme.transitionDuration` /
  `theme.transitionTimingFunction`.
- `animation` — literal `Record<string, string>` from
  `primitive.animations`. Plugs into UnoCSS `theme.animation`.
  Author-supplied `@keyframes` declarations are still required.

These plug directly into UnoCSS's `theme` config. Because every value is
a CSS variable, swapping the PrimeVue preset at runtime cascades to
every utility class without rebuilding.

## `shortcuts.ts` — UnoCSS shortcuts

Source: [generators/shortcuts.ts](../packages/core/src/generators/shortcuts.ts).
Exports: `generateShortcuts`.

Output (default `shortcuts.ts`) exports a single `shortcuts` record. For
every entry in `unocss.shortcuts`:

```ts
"bg-page": { light: "bg-surface-50", dark: "dark:bg-surface-950" }
```

is collapsed to:

```ts
"bg-page": "bg-surface-50 dark:bg-surface-950"
```

The dark variant prefix is applied verbatim — your `light`/`dark`
strings should already include any `dark:` prefix where needed.

## `palettes.ts` — Color palette catalog

Source: [generators/palettes.ts](../packages/core/src/generators/palettes.ts).
Exports: `generatePalettes`, `collectPalettes`, type `PaletteCatalog`.

Output (default `palettes.ts`) emits five `as const` exports describing
every color scale available to the config:

| Export | Shape | Contents |
| --- | --- | --- |
| `customPalettes` | `Record<name, ColorScale>` | All entries from `primitive.colors` with their hex values |
| `builtinPalettes` | `Record<name, ColorScale>` | All 22 builtin (Tailwind v3 / Aura) palettes with hex values |
| `referencedBuiltinPalettes` | `string[]` | Builtin names actually used by `semantic.primary`, `semantic.surface.{scale,darkScale}`, or `semantic.extra.*` |
| `shadowedBuiltinPalettes` | `string[]` | Custom palette names that shadow a builtin of the same name |
| `availableBuiltinPaletteNames` | `string[]` | Full list of builtin names you can reference |

Use it to render swatches in a docs/preview UI without hardcoding palette
names. The CLI's [`colors` subcommand](cli.md#colors-subcommand) prints
the same data as a terminal listing.
