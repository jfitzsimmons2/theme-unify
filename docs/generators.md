# Generators

All generators live in
[packages/core/src/generators](../packages/core/src/generators). Each one
exports two things:

1. A **string emitter** `generateXxx(resolved): string` — used by the CLI
   to write a `.ts` file.
2. (Optional) A **runtime builder** `buildXxxObject(resolved): object` —
   used at runtime by the playground's token editor to apply changes
   without disk IO.

Shared helpers — `fileHeader()`, `serializeValue()`, `serializeObject()`,
`buildSurfaceObject()` — live in
[utils.ts](../packages/core/src/generators/utils.ts).

## Emit conventions

- Every file starts with `fileHeader()`:
  ```
  // Auto-generated by theme-unify — do not edit
  ```
- All exports use `as const` where it sharpens types in consumers.
- Object keys that aren't valid JS identifiers are quoted by
  `serializeObject`.
- Strings use single quotes; backslashes and quotes are escaped.
- Indentation is 2 spaces (`INDENT` in `utils.ts`).

## `primevue.ts` — styled-mode preset

Exports: `generatePrimeVue`, `buildPrimeVuePreset`.

Output file (default `primevue-preset.ts`) exports a single
`GeneratedPreset` produced by
`definePreset(BaseTheme, { semantic, colorScheme, components })`.

What it does:

- Maps `semantic.colors.<role>.scale` → a full color object (`50`–`950`)
  for each PrimeVue color role. The scale name may be a key in
  `primitive.colors` or a [builtin palette](token-schema.md#builtin-palettes)
  (`purple`, `sky`, `indigo`, …).
- Builds the `surface` palette via `buildSurfaceObject`, optionally
  inverted in dark mode.
- Auto-generates `primary`/`highlight`/`formField` defaults.
- Deep-merges `primevue.colorScheme`, `focusRing`, `formField`,
  `components` overrides on top.

Consumed by the playground's
[main.ts](../packages/playground/src/main.ts) as `theme.preset`.

## `primevue-pt.ts` — unstyled-mode passthrough

Exports: `generatePrimeVuePT`, `buildPrimeVuePTObject`.

Output file (default `primevue-pt.ts`) exports a `primevuePT` object whose
shape matches PrimeVue's PT API: `Record<componentName, Record<section,
string | (ctx) => string>>`.

The generator builds two internal class maps from `semantic` (see
`PTSeverityClassMap` and `PTSurfaceClassMap` in
[types.ts](../packages/core/src/types.ts)):

- **Severity map** — for each role (`primary`, `secondary`, `success`,
  `info`, `warn`, `danger`, `help`, `contrast`): `bg`, `bgHover`,
  `bgActive`, `text`, `border`, plus subtle/outlined variants.
- **Surface map** — `pageBg`, `surfaceBg`, `elevatedBg`, `cardBg`, `text`,
  `textMuted`, `border`, `inputBg`, `inputBorder`, `inputBorderHover`,
  `inputBorderFocus`.

These class strings are then composed into PT entries for ~20 components
(Button, Card, InputText, Select, DataTable, Dialog, Drawer, Message,
Toast, Tag, Badge, Panel, Accordion, Tabs, Menu, Menubar, Breadcrumb,
Avatar, ProgressBar, …). Full list and per-component sections are tracked
in [UNSTYLED-PLAN.md](../UNSTYLED-PLAN.md#step-12-create-generatorsprimevue-ptts-new).

> **Important**: any class string emitted by this generator must be
> reachable by UnoCSS at build time. The playground configures
> `content.filesystem: ['src/generated/primevue-pt.ts']` in
> [uno.config.ts](../packages/playground/uno.config.ts) so dynamic class
> names get scanned.

## `unocss-theme.ts` — UnoCSS theme

Exports: `generateUnoCSS`.

Output file (default `unocss-theme.ts`) exports five named consts (all
`as const`):

- `colors` — every primitive color scale, plus any [builtin
  palettes](token-schema.md#builtin-palettes) referenced via
  `semantic.colors` or `semantic.surface`, plus the surface palette
  derived from `semantic.surface`, plus aliases from
  `unocss.colorAliases`. Builtins that aren't referenced are omitted to
  keep the generated bundle lean.
- `borderRadius`, `boxShadow`, `fontFamily`, `fontWeight` — flat copies of
  the corresponding `primitive` sections.

These plug directly into UnoCSS's `theme` config.

## `unocss-shortcuts.ts` — UnoCSS shortcuts

Exports: `generateShortcuts`.

Output file (default `unocss-shortcuts.ts`) exports a single `shortcuts`
record. For every entry in `unocss.shortcuts`:

```ts
'bg-page': { light: 'bg-chickpea-50', dark: 'dark:bg-chickpea-950' }
```

is collapsed to:

```ts
'bg-page': 'bg-chickpea-50 dark:bg-chickpea-950'
```

The dark variant prefix is applied verbatim — the user's `light`/`dark`
strings should already include any `dark:` prefix where needed (matching
the existing fixtures).
